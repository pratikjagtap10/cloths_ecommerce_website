==========================================================================================
        E-COMMERCE CLOTH STORE  -  LOCAL DEVELOPMENT PLAN (MICROSERVICE ARCHITECTURE)
        Stack: Next.js + React | Python + Django | FastAPI | PostgreSQL | Redis | Docker
==========================================================================================

GOAL
----
Build a working clothing store on your local machine that covers the basic concepts of
frontend, backend and microservice communication, packaged with Docker for shipping.

The project is split into separate services. Each one has its own code, its own
Dockerfile and its own job:

  1. FRONTEND SERVICE   -> Next.js (React) - the storefront UI
  2. BACKEND SERVICE A  -> Django + Django REST Framework (DRF) - "Core Service"
                           (users, auth, product catalog, orders, admin panel)
  3. BACKEND SERVICE B  -> FastAPI - "Cart & Payment Service"
                           (cart, checkout, mock payment, inventory check, notifications)

Supporting containers: PostgreSQL (database), Redis (cache + message broker),
Nginx (API gateway / reverse proxy).


==========================================================================================
1. HIGH-LEVEL ARCHITECTURE
==========================================================================================

                         +------------------------+
     Browser  ---------> |   NGINX (API Gateway)  |  :80
                         +-----------+------------+
                                     |
         +---------------------------+------------------------------+
         | /                         | /api/core/*                  | /api/shop/*
         v                           v                              v
 +----------------+        +--------------------+  REST (sync)  +----------------------+
 |  FRONTEND      |        |  CORE SERVICE      | <-----------> |  CART/PAYMENT SVC    |
 |  Next.js :3000 |        |  Django DRF :8000  |               |  FastAPI :8001       |
 +----------------+        +---------+----------+               +----------+-----------+
                                     |                                     |
                                     |      Redis Pub/Sub / Queue (async)  |
                                     +---------------> REDIS <-------------+
                                     |                 :6379               |
                              +------+------+                       +------+------+
                              | Postgres DB |                       | Postgres DB |
                              |  core_db    |                       |  shop_db    |
                              +-------------+                       +-------------+

Key rule of microservices: "database per service". Django never reads shop_db, and
FastAPI never reads core_db. They only talk through APIs or events.

PHASE 3 - MICROSERVICE COMMUNICATION (Days 10-11)
------------------------------------------------------------------------------------------
Learn BOTH styles:

A) SYNCHRONOUS (Request/Response over REST)
   - FastAPI -> Django: "Is this variant in stock? What is its price?"
   - Caller waits for the answer. Simple, but couples services (if Django is down,
     cart add fails).
   - Secure with an internal API key header: X-Internal-Key
   - Use service names as hostnames inside Docker: http://core_service:8000

B) ASYNCHRONOUS (Event-driven via Redis Pub/Sub, or Redis Streams / Celery)
   - FastAPI publishes event:  "payment.succeeded" {order_id, amount}
   - Django subscriber listens -> updates Order.status = PAID and reduces variant stock
   - Django publishes event:   "order.shipped" {order_id, user_id}
   - FastAPI (or a worker) listens -> logs notification
   - Caller does NOT wait. Services are loosely coupled.

C) SHARED AUTHENTICATION
   - Django issues JWT -> frontend stores it -> sends "Authorization: Bearer <token>"
     to BOTH services -> each service verifies independently.

D) API GATEWAY (Nginx)
   - One entry point for the browser (localhost)
   - Routes /api/core/* -> Django, /api/shop/* -> FastAPI, / -> Next.js
   - Avoids CORS headaches and hides internal service ports

Checkout flow (end-to-end):
   1. User clicks "Place Order" in Next.js
   2. Next.js -> POST /api/shop/checkout/ (via Nginx)
   3. FastAPI reads cart -> calls Django /internal/variants/ to re-verify stock & price
   4. FastAPI -> POST Django /internal/orders/  (order created, status PENDING)
   5. FastAPI creates Payment (PENDING) -> returns to frontend
   6. User confirms mock payment -> FastAPI marks Payment SUCCESS
   7. FastAPI publishes "payment.succeeded" to Redis
   8. Django subscriber -> Order = PAID, stock reduced
   9. FastAPI clears cart, background task "sends" confirmation email
  10. Frontend shows Order Success page -> fetches order from Django
